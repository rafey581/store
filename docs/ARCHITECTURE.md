# Architecture

> Status: Phases 1–3 (website, admin, payments) are built. `mobile/` (Phase 4, Android admin app) is not built yet.
> Small differences from the original proposal: local uploads are served by `/media/[...key]`; the proof review page is `/admin/proofs`.

## Stack

| Concern | Choice |
|---|---|
| Web app | Next.js 16 (App Router) + TypeScript + Tailwind CSS |
| DB | PostgreSQL on Supabase, Prisma 7 (`@prisma/adapter-pg`) |
| Validation | Zod 4, schemas shared by route handlers, server actions and forms |
| Web auth | Auth.js (`next-auth@5`), credentials provider, JWT session cookie |
| Mobile auth | `/api/mobile/auth/*`: 15-min access JWT + rotating refresh token (`RefreshToken` table) |
| File storage | Supabase Storage: `product-images` (public), `payment-proofs` (private, signed URLs) |
| Email | Resend (or SMTP via Nodemailer), switched by env var |
| Cron | Vercel Cron → `/api/cron/expire-orders` (protected by `CRON_SECRET`) |
| Mobile | Expo (React Native + TypeScript), Expo Router, EAS Build → APK |
| Push | Expo Push Service (tokens in `PushDevice`) |

## Key rules and where they are enforced

| Rule | Where |
|---|---|
| Money is integer paisa | Schema (`*Paisa Int`), `lib/money.ts` is the only place that formats rupees |
| Amounts computed on server | `server/pricing` recomputes from DB prices at checkout; client totals are display only |
| Order becomes PAID only from a verified callback or admin approval | `server/payments` is the only code that writes `paymentStatus = PAID`; browser return pages only *read* status |
| Idempotent callbacks | `PaymentEvent @@unique([method, eventKey])` + status check inside a transaction |
| Expire unpaid orders, release stock | Cron job: `PENDING_PAYMENT` orders past `expiresAt` → `EXPIRED`, `InventoryMovement(ORDER_RELEASED)`, coupon redemption removed |
| No overselling | Stock decremented with a conditional `UPDATE ... WHERE stock >= qty` inside the order transaction |
| Roles checked on server | `requireRole()` in every admin layout, server action and `/api/mobile/*` handler; middleware is only a convenience redirect |
| Gateway keys only in env | `server/payments/providers/*` read `process.env`; `StoreSettings` holds on/off toggles only |
| Payment screenshots are private | Private bucket; admins get short-lived signed URLs |

## Roles

| Permission | Owner | Staff |
|---|:-:|:-:|
| Dashboard, products, categories, inventory | ✓ | ✓ |
| Orders: view, change status, add tracking | ✓ | ✓ |
| Approve / reject payment proofs | ✓ | ✓ |
| Customers: view | ✓ | ✓ |
| Coupons, shipping rates | ✓ | ✓ |
| Store settings, manual payment accounts | ✓ | — |
| Staff management | ✓ | — |
| Refunds / cancel paid orders | ✓ | — |

## Order and payment state flow

```
              place order (stock reserved)
                        │
                        ▼
              PENDING_PAYMENT ──(expiresAt passed, cron)──► EXPIRED (stock released)
               │            │
   gateway callback      proof uploaded
   (verified, amount        │
    matches)                ▼
               │       PAYMENT_REVIEW ──admin rejects──► PENDING_PAYMENT (can re-upload)
               │            │
               │       admin approves
               ▼            ▼
                      PAID ──► PROCESSING ──► SHIPPED (tracking no.) ──► DELIVERED
                        │
                        └──► CANCELLED / REFUNDED (Owner)
```
